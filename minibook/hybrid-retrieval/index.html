Hybrid Retrieval

Lexical, semantic, relational, and spatial evidence

Design hybrid retrieval as a multi-channel candidate and ranking system, distinct from any single vector or BM25 index.

01

Hybrid retrieval preserves different evidence

Lexical retrieval rewards explicit terms while vector retrieval captures semantic proximity. Neither is a fallback implementation of the other; hybrid systems retain both signals for candidate generation and ranking.

  • Keep channel scores and ranks visible.
  • Use the same corpus and query snapshot for comparison.
  • Define which failure each channel is expected to recover.

02

Candidate generation sets the ceiling

Fusion cannot recover a relevant document absent from every candidate list. Candidate depth, analyzer behavior, ANN recall, filters, and per-channel limits determine the pool before ranking begins.

  • Measure channel recall before fusion quality.
  • Allocate candidate budgets by query cohort.
  • Record truncated and filtered candidates.

03

Scores are not naturally comparable

BM25-like scores, cosine distance, spatial distance, and business priors have unrelated scales. Reciprocal-rank fusion combines order rather than pretending raw values share units.

  • Handle missing ranks explicitly.
  • Tune fusion constants on judgments.
  • Retain deterministic tie-breaking.

04

Relational constraints remain first-class

Tenant, authorization, time, inventory, and geography may be eligibility rules rather than relevance hints. Enforce mandatory constraints in every retrieval path before returning results.

  • Separate hard filters from soft boosts.
  • Test leakage with adversarial tenants and permissions.
  • Measure recall within the eligible population.

05

Reranking spends a bounded budget

A more expensive model can rerank a small fused candidate set, but it cannot repair omissions upstream. Latency, token cost, and failure behavior require an explicit budget.

  • Version prompts and reranking models.
  • Cache only under a defined freshness policy.
  • Return a stable result when the reranker is unavailable.

06

Evaluation must diagnose channels

A single top-k metric hides why hybrid retrieval improved or regressed. Evaluate lexical-only, vector-only, fused, filtered, and reranked stages across navigational, semantic, rare-term, and local queries.

  • Keep human relevance judgments.
  • Report quality with latency percentiles.
  • Inspect wins and losses per cohort.

Field manual

Concrete mechanics, diagnostic evidence, and executable patterns to carry into a real system.

01

Retain independent candidate lists

Run lexical and semantic retrieval independently and preserve ranks before fusion. This makes omissions and channel-specific regressions diagnosable.

lexical = top_n_bm25(query, 100)
semantic = top_n_vector(embed(query), 100)
# Persist document ID, rank, raw score, index version, and filter.
02

Fuse with reciprocal ranks

RRF avoids assuming that lexical scores and vector distances have the same scale. Missing candidates contribute zero from that channel.

rrf(id) = sum(1 / (60 + rank[channel][id])
              for channel in channels if id in rank[channel])
03

Apply mandatory eligibility

Authorization and tenant predicates must constrain every candidate channel. A final filter is defense in depth, not permission to retrieve across boundaries carelessly.

eligible_lexical = lexical_search(query, tenant_id, acl)
eligible_vector = vector_search(embedding, tenant_id, acl)
assert all(can_read(user, row) for row in fuse(...))
04

Evaluate retrieval stages

Compare channel, fusion, and reranking quality using the same judgments. Report latency and candidate counts so a quality gain has an explicit cost.

stages = ['lexical', 'vector', 'fused', 'reranked']
for stage in stages:
  report(nDCG_at_10, recall_at_100, p95_ms, candidates)
