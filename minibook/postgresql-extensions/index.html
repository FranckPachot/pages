PostgreSQL Extensions

Capability, trust, packaging, upgrades, and governance

Operate PostgreSQL extensions as versioned executable dependencies with explicit privileges, packaging, compatibility, observability, and recovery tests.

01

Extensions are executable dependencies

An extension can add SQL objects, planner hooks, access methods, background workers, and native code inside the database process. Installation therefore changes both capability and the trusted computing base.

  • Inventory code origin and maintainers.
  • Review required privileges and native libraries.
  • Treat extension approval as production change control.

02

Control files bind SQL to binaries

PostgreSQL discovers extension metadata and versioned scripts from the installation. CREATE EXTENSION records a managed object set, but operating-system packages must already match the server major version and architecture.

  • Separate package installation from database activation.
  • Verify available and installed versions.
  • Do not copy shared libraries between incompatible builds.

03

Upgrade paths are explicit

ALTER EXTENSION UPDATE follows declared version transitions; it is not a generic promise that an extension supports a new PostgreSQL release. Dependencies, stored data formats, and catalog objects need rehearsal.

  • Test every intermediate update path.
  • Back up extension-owned data and definitions.
  • Validate downgrade or rollback constraints.

04

Portability depends on the platform

Managed services and PostgreSQL-compatible systems expose approved subsets or require different builds. SQL portability does not imply extension ABI, hook, or background-worker portability.

  • Check the target platform's supported list.
  • Confirm feature behavior, not only CREATE success.
  • Keep a no-extension migration option for critical data.

05

Planner hooks need observability

Hinting and statistics extensions can change plans without changing application SQL. Their configuration and matching rules become part of reproducibility and incident evidence.

  • Capture loaded libraries and extension versions.
  • Retain plan output with applied hints.
  • Prefer repairing estimates before permanent coercion.

06

Governance prevents extension sprawl

Each extension adds patching, security, backup, replication, and upgrade obligations. A registry with owner, purpose, version, data footprint, and removal test keeps convenience from becoming hidden infrastructure.

  • Remove only after dependency discovery.
  • Rehearse restore on a clean server.
  • Monitor upstream advisories and release cadence.

Field manual

Concrete mechanics, diagnostic evidence, and executable patterns to carry into a real system.

01

Inventory installed and available versions

Join installed extensions with the versions available on this server before planning an update or major-version migration.

SELECT e.extname, e.extversion, a.default_version, e.extnamespace::regnamespace
FROM pg_extension e LEFT JOIN pg_available_extensions a ON a.name=e.extname
ORDER BY e.extname;
02

Inspect extension-owned objects

Extension membership identifies objects managed by extension scripts. External dependencies still need separate discovery before removal.

SELECT e.extname, d.classid::regclass, d.objid,
       pg_describe_object(d.classid,d.objid,d.objsubid)
FROM pg_depend d JOIN pg_extension e ON e.oid=d.refobjid
WHERE d.deptype='e' ORDER BY e.extname;
03

Rehearse version transitions

Build a clean instance with production package versions, restore representative data, execute supported extension updates, and validate objects and behavior.

SELECT * FROM pg_available_extension_versions
WHERE name = $1 ORDER BY version;
ALTER EXTENSION extension_name UPDATE TO 'target_version';
04

Capture preload configuration

Planner hooks and background workers may depend on preload settings and restart. Retain these settings with extension versions in incident evidence.

SHOW shared_preload_libraries;
SHOW session_preload_libraries;
SELECT name, setting, source, pending_restart
FROM pg_settings WHERE name LIKE '%preload_libraries';
